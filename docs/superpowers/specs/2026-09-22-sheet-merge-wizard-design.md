# 시트 통합 마법사 UX 개편 설계

## 목적

처음 사용하는 사용자가 별도 매뉴얼을 먼저 읽지 않아도 여러 시트를 같은 헤더 기준으로 통합할 수 있게 한다. 기존 통합 계산, 자동 ID, 관리코드, 통합 시트 분리 기능은 유지하고 설정 및 검토 흐름만 단계형 UI로 재구성한다.

## 현재 문제

- 한 화면에 시트, KEY, ID, 헤더 행, 헤더 구조, 표시행, 출력 열과 결과 위치가 동시에 노출된다.
- `KEY`, `ID`, `헤더 구조`, `표시행` 용어가 설명 없이 먼저 등장한다.
- KEY 직접 지정은 설정창을 닫은 뒤 시트별 범위 선택창으로 이어져 현재 단계를 알기 어렵다.
- 매칭 검토창은 읽기 전용이며 수정하려면 전체 작업을 다시 시작해야 한다.
- `통합 표시행`을 먼저 실행해야 하는 것처럼 보이지만 일반적인 헤더 통합에는 필요하지 않다.

## 설계 원칙

- 기본 흐름은 자동 감지 결과를 확인하고 다음 단계로 진행하는 방식으로 한다.
- 고급 옵션은 필요할 때만 펼친다.
- 한 화면에서는 한 가지 결정만 요구한다.
- 실행 전에 누락 열, 자동 ID, 원본 변경 여부를 명확히 보여준다.
- 잘못된 설정을 발견하면 `이전`으로 돌아가 수정할 수 있어야 한다.

## 사용자 흐름

### 1단계: 원본 시트 선택

- 제목: `1. 통합할 시트 선택`
- 통합 가능한 워크시트를 체크 목록으로 표시한다.
- 현재 통합 결과 시트와 숨김 내부 시트는 기본 선택에서 제외한다.
- 각 시트 옆에 감지한 헤더 행과 데이터 행 수를 표시한다.
- `전체 선택`, `전체 해제`, `다음`과 `취소` 버튼을 제공한다.
- 하나 이상의 시트를 선택해야 다음 단계로 이동할 수 있다.

### 2단계: 열과 ID 설정

- 제목: `2. 가져올 열과 ID 설정`
- 선택한 시트에서 감지한 헤더의 합집합을 체크 목록으로 표시한다.
- 모든 선택 시트에 존재하는 헤더는 기본 선택하고, 일부 시트에만 존재하는 헤더는 `일부 시트만 있음` 상태를 표시한다.
- ID 방식은 다음 라디오 버튼으로 제공한다.
  - `ID 자동 생성`을 기본값으로 사용한다.
  - `기존 열을 ID로 사용`을 선택하면 헤더 드롭다운을 활성화한다.
  - `시트별로 다른 ID 열 지정`을 선택하면 시트별 ID 헤더 목록을 표시한다.
- 결과 시트 이름과 생성 위치를 이 단계에서 지정한다.
- `고급 설정`을 펼치면 헤더 행, 1줄/2줄 헤더 구조, 표시행 기준, 원본 시트 ID 생성 옵션을 표시한다.
- 표시행은 기존 사용자를 위한 호환 기능이며 기본값은 끔으로 둔다.

### 3단계: 매칭 검토 및 실행

- 제목: `3. 통합 결과 확인`
- 선택 시트 수, 예상 데이터 행 수, 결과 시트명, ID 처리 방식을 요약한다.
- 헤더별로 각 시트의 매칭 열을 표 형태로 보여준다.
- 상태는 `정상`, `일부 누락`, `확인 필요`, `원본 변경` 네 가지 문구로 표시하고 색상만으로 구분하지 않는다.
- 누락된 헤더는 해당 시트에서 빈값으로 생성된다는 설명을 바로 표시한다.
- `이전`, `통합 실행`, `취소` 버튼을 제공한다.
- `이전`을 누르면 입력값을 유지한 채 2단계로 돌아간다.

## UI 구조

기존 `frmDatabaseMergeSetup`을 세 단계 MultiPage UserForm으로 교체한다. 별도의 읽기 전용 `frmDatabaseMergeReview`는 제거하고 3단계에 통합한다.

UserForm은 다음 데이터를 보관한다.

- 선택 시트 목록
- 자동 감지된 헤더 행과 헤더 목록
- 선택 출력 헤더
- ID 방식과 시트별 ID 열
- 결과 시트 이름과 위치
- 고급 헤더 설정과 표시행 사용 여부

마법사는 `preview`, `run`, `back`, `cancel` 동작 상태를 반환한다. 2단계에서 `다음`을 누르면 폼을 언로드하지 않고 잠시 숨긴다. VBA가 기존 `DBMerge_BuildPlan`으로 계획을 계산한 뒤 같은 폼에 요약과 매칭표를 전달하고 3단계를 표시한다. `이전`은 보관된 입력값을 유지한 채 2단계를 다시 표시한다.

시트별 ID 직접 지정도 폼 안에서 헤더명을 선택하는 방식으로 완료한다. 기존의 시트별 범위 선택 팝업은 마법사 경로에서 사용하지 않는다.

기존 리본의 `시트 통합` 버튼은 새 마법사를 연다. `통합 표시행` 버튼은 고급 사용자 호환을 위해 유지하되 리본 설명에 선택 기능임을 명시한다.

## 데이터 흐름

1. VBA가 활성 통합 문서의 시트와 헤더 후보를 분석한다.
2. 분석 결과를 마법사에 전달한다.
3. 사용자가 시트와 열을 선택하면 마법사가 설정 문자열을 반환한다.
4. 기존 `DBMerge_BuildPlan`으로 통합 계획을 만든다.
5. 계획 요약과 매칭 표를 마법사 3단계에 표시한다.
6. 사용자가 이전을 누르면 계획을 폐기하고 입력값을 유지한다.
7. 실행을 누르면 기존 `DBMerge_WriteMergedSheet`를 호출한다.

통합 결과 형식과 `__DBMERGE_*` 관리코드는 변경하지 않는다. 따라서 기존 `통합 시트 분리` 기능과의 호환성을 유지한다.

## 오류 및 복구

- 시트 미선택, 열 미선택, 빈 결과 시트명은 해당 단계에서 즉시 안내하고 포커스를 이동한다.
- 자동 헤더 감지 실패 시 해당 시트를 `확인 필요`로 표시하고 고급 설정에서 행 번호를 입력하게 한다.
- 결과 시트명이 원본 시트와 같으면 2단계에서 진행을 막는다.
- 원본 ID 생성 옵션은 3단계에서 `원본 변경` 경고를 표시한다.
- 통합 실행 오류 시 화면 갱신 상태를 복구하고 원인을 메시지로 표시한다.

## 접근성 및 사용성

- 모든 입력에는 고정 라벨을 둔다.
- 탭 순서는 화면의 위에서 아래, 왼쪽에서 오른쪽 순서로 맞춘다.
- 상태는 색상과 텍스트를 함께 사용한다.
- 버튼 문구는 `다음`, `이전`, `통합 실행`, `취소`로 일관되게 한다.
- 긴 시트명과 헤더명은 가로 스크롤 또는 충분한 열 너비로 확인할 수 있게 한다.
- 폼 크기 안에서 모든 버튼이 보이도록 고정하고, 기존 배포 해상도에서 잘림을 확인한다.

## 한글 인코딩 안전 규칙

- `.bas`, `.md` 편집 원본은 UTF-8을 유지하고, 한글이 포함된 `.ps1`은 Windows PowerShell 5.1 호환을 위해 UTF-8 BOM으로 저장한다.
- Excel VBA 가져오기용 CP949 변환은 배포 스크립트에서만 수행한다.
- 한글 UI를 수정한 뒤 변경 파일을 UTF-8로 다시 읽고 `?ㅏ`, `吏`, `怨듭떇`, `寃` 등 깨진 문자열 패턴을 검사한다.
- 인코딩 오류가 발견되면 추측해서 치환하지 않고 UTF-8 원본 또는 정상 커밋에서 문구를 복원한다.
- 배포 중 VBA 보호는 화면 클릭이나 키 입력을 사용하지 않고 패키지 내부 프로젝트 스트림에 적용하며, Excel 재열기 검사에서 잠금이 확인되지 않으면 배포를 실패 처리한다.

## 코드 변경 범위

- `scripts/publish_release.ps1`: 새 3단계 UserForm 생성 코드와 리본 설명 수정
- `src/MacroToolkit.bas`: 마법사 상태 전환, 헤더 감지 결과 전달, 계획 미리보기와 실행 연결
- `tests/`: 단계 이동, 기본값, 설정 직렬화, 기존 통합 결과 호환에 대한 최소 회귀 테스트
- `docs/USER_MANUAL.md`: 새 3단계 사용법과 고급 설정 설명
- 버전: `1.1.47`

## 검증 기준

- ID가 있는 1줄 헤더 시트 여러 개를 기본값만으로 통합할 수 있다.
- ID가 없는 시트는 별도 설정 없이 자동 ID로 통합된다.
- 2줄 헤더와 표시행 방식은 고급 설정에서 기존 결과와 동일하게 동작한다.
- 시트별 KEY 열이 달라도 2단계에서 지정하고 통합할 수 있다.
- 3단계에서 일부 누락 헤더와 원본 변경 경고를 확인할 수 있다.
- 3단계에서 2단계로 돌아가도 선택값이 유지된다.
- 생성된 통합 시트를 기존 분리 기능으로 다시 나눌 수 있다.
- UserForm의 버튼과 텍스트가 폼 경계 밖으로 잘리지 않는다.
- 한글 문자열의 인코딩 손상 여부를 배포 전에 검사한다.
