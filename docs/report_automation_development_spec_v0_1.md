## 1. 개발 목표

엑셀 집계표를 읽어 보고서 본문에 사용할 핵심 수치를 자동 인식하고, 사용자가 지정한 문장 형식과 작성 논리에 따라 분석문, 차트/그래프, 보고서 삽입용 집계표를 생성한다. 이후 아래아한글 자동화 API 또는 PowerPoint 템플릿을 통해 완성형 보고서 초안을 자동 생성한다.

1차 목표는 Excel 안에서 검증 가능한 산출물을 만드는 것이다. VBA 실행 단계의 최종 산출물은 Excel 산출 시트이며, 한글 또는 PowerPoint 보고서 생성은 사용자가 이후 선택해서 실행하는 별도 단계로 둔다.

상위 제품 목표는 사회조사, 공공조사, 정책연구, 제안서, 시장규모 추정, 설문기획, 표본설계, 데이터 분석 보고서 작성 과정을 하나의 자동화 흐름으로 묶는 것이다. 다만 본 문서의 1차 구현 범위는 엑셀 집계표 기반 분석문/삽입표/차트데이터 생성이며, Markdown/Word/PDF/설문/방법론/출처관리 기능은 같은 아키텍처 위의 확장 단계로 둔다.

현재 확정된 방향:
- VBA 단계의 최종 산출물은 `보고서_분석문`, `보고서_차트데이터`, `보고서_삽입표`, `_ReportMeta`이다.
- HWP/PPT 보고서 생성은 사용자가 선택 실행하는 후속 작업이다.
- 집계표를 이미지로 삽입하는 방식은 허용하지 않는다.
- HWPX 직접 생성은 후순위로 두고, HWP COM 저장/변환 가능성을 먼저 검증한다.
- 초기 테스트 단계에서는 Python 워커를 `.exe`로 패키징하지 않고 소스 실행 방식으로 검증한다.
- 비율 표기는 기본적으로 소수점 1자리까지 표시한다.
- 차트는 이미지 삽입을 허용하되, HWP에서는 선택 붙여넣기 방식의 메타파일 삽입을 우선한다.
- Python 테스트 실행 환경은 프로젝트 폴더 안의 가상환경을 기준으로 한다.
- 기본 문체는 공적·전문적 조사보고서 문체이며, 문장 종결은 `~함`, `~임`, `~필요`, `~가능`을 우선한다.
- 모든 수치 문장은 기준, 단위, 표본수/모수, 응답 기준을 추적할 수 있어야 한다.
- 출처가 필요한 외부 사실은 출처 확인 필요 상태를 남기고, 확인 전 단정적으로 작성하지 않는다.

## 2. 현재 샘플 집계표 구조 요약

샘플 통합문서 구조:
- 시트: `INDEX`, `Sheet1`
- `INDEX`: 131행 x 4열, 표 제목과 이동 링크 역할
- `Sheet1`: 8,863행 x 78열, 실제 집계표 127개가 세로로 이어진 구조

표 블록 패턴:
- 표 제목 행: A열 값이 `[표 ...]`로 시작
- 예: `[표 MDBR-6 > [리스트 기준] 대분류(6종)별 사업체 분포 현황]`
- 표 제목 다음 행: `BASE:전체`, `BASE:전체응답자` 등 모집단/응답 기준
- 헤더 행: `사례수`, `N`, `%`, 평균 등 측정값
- 데이터 행:
  - `■ 전체`: 전체 기준 행
  - `▣ ...`: 행 그룹 시작
  - A열이 비어 있고 B열에 항목명이 있으면 직전 그룹의 하위 항목
- 값 표현:
  - 사례수/N은 `(549567)`처럼 괄호 문자열로 들어오는 경우가 많음
  - 비율은 숫자 실수로 들어오며 보고서에서는 보통 소수점 1자리 또는 정수 반올림 사용
  - 일부 표에는 `▶평균◀(명)` 같은 평균 열이 함께 존재

대표 표 유형:
- 단일 전체 분포표: 전체 기준 N/%만 있는 표
- 배너 교차표: 행 그룹 x 열 그룹의 `%` 중심 표
- N/% 쌍 표: 각 열 항목마다 `N`, `%`가 반복되는 표
- 평균 포함 표: 분포표 마지막에 평균/합계 열이 있는 표

주의할 점:
- 같은 문항 ID가 반복될 수 있다. 예: `SQ2`가 서로 다른 제목으로 등장
- 병합 셀이 많으므로 셀 값만 읽으면 상위 헤더가 누락될 수 있다.
- `?`로 보이는 문자는 원본 특수문자 또는 인코딩 치환일 수 있으므로 사용자 검토가 필요하다.
- 표 제목, 행 위치, 원본 범위를 보존해야 추후 한글/PPT 삽입 결과를 추적할 수 있다.

## 3. 전체 업무 흐름

1. 사용자가 집계표 통합문서를 선택한다.
2. 프로그램이 표 블록을 탐지하고 `표ID`, 제목, BASE, 행/열 구조, 원본 범위를 메타데이터로 만든다.
3. 사용자가 분석 대상 표와 작성 규칙을 선택한다.
4. 프로그램이 분석문 초안, 차트 데이터, 보고서용 축약표를 생성한다.
5. 결과를 새 시트에 저장하고 사용자가 검토/수정한다.
6. 여기까지가 VBA 단계의 기본 완료 지점이다.
7. 사용자가 후속 작업으로 한글 또는 PowerPoint 출력 형식을 선택한다.
8. 사용자가 별도 템플릿을 지정하지 않으면 프로그램이 기본 HWP/HWPX/PPTX 템플릿을 새 파일로 생성한다.
9. 프로그램이 템플릿의 필드/자리표시자에 분석문, 표, 차트를 삽입한다.
10. 산출 파일과 실행 로그를 저장한다.

## 4. 기능 범위

### 4.1 Excel 집계표 인식

필수 기능:
- `INDEX` 시트가 있으면 표 목록 후보로 사용한다.
- 실제 표 위치는 원본 시트에서 A열 `[표 ...]` 패턴을 기준으로 재탐지한다.
- 각 표 블록의 시작 행, 종료 행, 마지막 사용 열을 계산한다.
- 표 제목에서 다음 값을 분리한다.
  - `table_no`: `0`, `0-1`, `MDBR-6`, `SQ1-3` 등
  - `title`: `응답자 특성`, `대표자 성별` 등
  - `basis`: `[리스트 기준]`, `[응답 기준]` 등 제목 안의 기준 표현
- BASE 행을 읽어 분석 기준을 저장한다.
- 헤더 행을 정규화해 열 메타데이터를 만든다.
- 데이터 행을 그룹/항목/값 구조로 변환한다.

내부 데이터 모델:

```text
ReportWorkbook
  - source_file
  - source_sheet
  - tables: TableBlock[]

TableBlock
  - table_key: 원본 순번 기반 고유 키
  - table_no: 제목 안 표 번호
  - title
  - basis
  - base_label
  - source_range
  - header_rows
  - columns: ColumnSpec[]
  - rows: RowSpec[]
  - values: CellValue[]

ColumnSpec
  - column_index
  - group_label
  - item_label
  - measure: 사례수 | N | % | 평균 | 기타

RowSpec
  - row_index
  - group_label
  - item_label
  - is_total

CellValue
  - row_key
  - column_key
  - raw_value
  - numeric_value
  - display_value
```

탐지 우선순위:
1. 표 제목 행 탐지
2. 블록 범위 산정
3. 병합 헤더 보정
4. 측정값 열 식별
5. 행 그룹 전파
6. 숫자/비율/평균 값 정규화
7. 검토 필요 항목 로그 기록

### 4.2 사용자 지정 작성 논리

사용자는 시트 또는 UserForm에서 분석문 생성 규칙을 지정한다.

초기 MVP에서는 `보고서_설정` 시트를 생성해 다음 항목을 받는다.

기본 설정:
- 프로젝트ID
- 프로젝트명
- 보고서명
- 프로젝트 유형: 공공조사 / 정책연구 / 제안서 / 방법론 / 설문기획 / 데이터분석
- 산출물 유형: Excel 산출 시트 / HWP / PPTX / Markdown / Word / PDF
- 문체 프로필: 공공조사 보고서형 / 제안서형 / 발표자료형 / 회의록형
- 분석 대상 표 선택 방식: 전체 / 선택 표 / 표ID 목록
- 문체: 공식 보고서체 / 간결체 / 발표자료체
- 수치 표기: 소수점 1자리 기본, 옵션으로 0자리 / 2자리 선택
- N 표기 여부: 표시 / 숨김
- 비교 기준: 전체 대비 / 행 그룹 내 비교 / 열 그룹 내 비교
- QA 실행 여부: 수치 QA / 문체 QA / 표 서식 QA / 출처 QA
- 출처 관리 여부: 사용 / 사용 안 함
- 수정 이력 관리 여부: 사용 / 사용 안 함
- LLM 문장 고도화 사용 여부: 사용 / 사용 안 함
- LLM 제공자: OpenAI GPT / Anthropic Claude / 사용 안 함
- LLM API 키 입력 방식: 실행 시 입력 / 환경변수 사용 / 저장된 키 사용
- LLM 모델명

문장 논리:
- 상위 N개 강조
- 하위 N개 강조
- 전체 평균 또는 전체 비율 대비 높음/낮음 비교
- 1위와 2위 차이 강조
- 특정 항목만 설명
- 0 또는 결측 항목 제외
- 합계/계 열 제외

문장 템플릿 예:

```text
{표제}를 살펴보면, {1위항목}이 {1위값}%로 가장 높고, 다음으로 {2위항목} {2위값}%, {3위항목} {3위값}% 순으로 나타났다.
{집단명}에서는 {항목명} 비중이 {값}%로 전체({전체값}%)보다 {차이}p {높낮음}.
```

분석문 생성 원칙:
- 원자료 숫자를 변경하지 않는다.
- 보고서용 표시값은 별도 포맷 값으로 만든다.
- 순위 비교 시 동률 처리 규칙을 명시한다.
- 차이가 0.05%p 미만이면 같은 수준으로 표현한다.
- 표본 수 또는 가중 사례수가 너무 작은 셀은 경고 표시한다.
- 분석문 기본 구조는 수치 → 해석 → 시사점 순서로 한다.
- 공공조사/정책연구 보고서에서는 `~함`, `~임`, `~필요` 문체를 우선 적용한다.
- 제안서/발표자료에서는 핵심 메시지형 문장을 허용한다.
- 기존 자료와 신규 제안, 사용자 지시와 자동 생성 의견은 구분해서 표시한다.
- 규칙 기반 분석문을 기본값으로 생성한다.
- GPT/Claude 등 LLM은 선택 기능으로 두며, 수치 계산이 아니라 문장 고도화와 표현 변형에만 사용한다.
- LLM에 전달하는 입력에는 표 제목, 검증된 주요 수치, 사용자가 선택한 문장 논리, 금지/주의 표현을 포함한다.
- LLM 결과는 `분석문_LLM` 열에 별도 저장하고, 사용자가 확인한 뒤 `최종 사용문`에 반영한다.
- API 키는 기본적으로 통합문서에 평문 저장하지 않는다. 저장이 필요하면 사용자 확인 후 마스킹 표시와 별도 보관 방식을 사용한다.

### 4.3 Excel 산출 시트 생성

프로그램은 원본 집계표 통합문서에 다음 시트를 생성한다.

#### `보고서_설정`

사용자 입력 및 실행 옵션 시트.

주요 영역:
- 프로젝트 정보
- 실행 범위
- 문체·서식 프로필
- 문장 템플릿
- LLM/API 설정
- QA 설정
- 출처 설정
- 표/차트 출력 옵션
- 한글/PPT 템플릿 경로
- 산출 파일 경로

#### `보고서_표목록`

자동 인식된 표 목록과 검토 상태.

열:
- 선택
- table_key
- table_no
- title
- basis
- base_label
- source_sheet
- source_range
- table_type
- row_count
- col_count
- warning

#### `보고서_분석문`

표별 분석문 결과.

열:
- table_key
- 문항/표 제목
- 분석문_기본
- 분석문_세부
- 분석문_LLM
- 주요 수치 JSON 또는 요약
- 검토 상태
- 사용자 수정문
- 최종 사용문

`최종 사용문`은 사용자가 수정문을 입력하면 수정문을 우선하고, 없으면 자동 생성문을 사용한다.

#### `보고서_차트데이터`

차트 생성에 쓰는 정규화 데이터.

열:
- table_key
- series_group
- category
- measure
- value
- display_value
- sort_order
- include_chart

#### `보고서_삽입표`

한글/PPT에 넣기 좋은 축약 집계표.

원칙:
- 원본 표를 그대로 복사하지 않고 보고서 본문에 적합한 폭으로 축약한다.
- 기본은 전체 행 또는 선택 행 그룹 중심으로 만든다.
- N/% 쌍은 사용자가 지정한 표시 방식에 따라 `%`만 또는 `N (%)`로 구성한다.
- 표 제목, 단위, 주석, 출처를 함께 둔다.

#### `_ReportMeta`

숨김 시트. 자동화 추적용 메타데이터를 저장한다.

저장 항목:
- 실행 시각
- 원본 파일명
- 표별 원본 범위
- 생성 시트 범위
- 한글/PPT 필드 매핑
- 프로젝트/문체 프로필
- 산출물 유형
- 오류/경고 요약

#### `보고서_QA`

자동 검토 결과 시트.

검토 항목:
- 수치 일치 여부
- 단위 누락 여부
- 표본수/모수/응답 기준 누락 여부
- 분석문과 표/차트 수치 일치 여부
- 문체 일관성
- 표 서식 검토 결과
- 출처 확인 필요 문장
- 사용자 지시 충돌 가능성

### 4.4 차트/그래프 생성

차트 생성 규칙:
- 단일 분포표: 가로 막대형 차트 우선
- 시계열이 아닌 항목 비교: 막대형 또는 누적 막대형
- 배너 교차표: 선택 행/열만 차트화
- 항목 수가 8개를 넘으면 상위 N개와 기타로 묶기 옵션 제공
- 평균 값은 별도 막대 또는 보조 주석으로 표시

MVP 차트:
- Excel 네이티브 차트 생성
- 차트 이름을 `chart_{table_key}` 형식으로 저장
- 한글/PPT 삽입을 위해 차트 원본 데이터 범위와 차트 객체명을 `_ReportMeta`에 기록
- 차트는 이미지 삽입을 허용한다.
- HWP 삽입 시에는 단순 비트맵 이미지가 아니라 선택 붙여넣기 방식의 메타파일 삽입을 우선한다.
- PPT 삽입 시에는 PPT 네이티브 차트, Excel 차트 객체 붙여넣기, 이미지 삽입 방식을 PoC에서 비교하되 기본 템플릿 품질과 편집 가능성을 우선한다.

### 4.5 아래아한글 자동화 연동

한글 API 기준:
- 최상위 OLE Automation 객체: `HwpFrame.HwpObject.2`
- 텍스트 삽입: `HAction.GetDefault("InsertText", HParameterSet.HInsertText.HSet)` 후 `Text` 설정 및 `HAction.Execute`
- 서식 제어: `CharShape`, `ParaShape`
- 표 생성: `TableCreate` Action + `TableCreation` ParameterSet
- 셀 테두리/배경: `CellBorderFill`
- 파일 저장: `FileSave`, `FileSaveAs`
- 템플릿 필드: `GetFieldList`, `MoveToField`, `PutFieldText`
- 보안 모듈: `RegisterModule` 필요 여부는 실행 환경에서 PoC로 확정
- 이벤트 핸들러: 저장/열기/닫기 감지 기능은 선택 기능으로 분리

권장 삽입 방식:

1단계 MVP:
- 한글 템플릿에 누름틀/필드명을 미리 둔다.
- 분석문은 `PutFieldText` 또는 `MoveToField` + `InsertText`로 삽입한다.
- 집계표는 한글 표로 직접 생성하는 방식을 우선한다.
- 차선책으로 Excel 범위 붙여넣기를 허용하되, 붙여넣기 후 표 서식을 제어할 수 있는 설정창을 제공한다.
- 집계표 이미지 삽입은 허용하지 않는다.

2단계 안정화:
- 표는 한글 `TableCreate`로 직접 생성하고 셀별 텍스트를 입력한다.
- 표 서식은 사전 정의 스타일을 적용한다.
- 차트는 HWP 선택 붙여넣기 기능으로 메타파일 형식 삽입을 우선 검토한다.

표 서식 설정창 필수 항목:
- 표 전체 글꼴, 글자 크기, 줄 간격
- 제목 행/배너 행/데이터 행 글꼴 크기
- 내부 선 굵기와 선 종류
- 외곽 선 굵기와 선 종류
- 배너 구분선 굵기와 선 종류
- 헤더 배경색과 데이터 행 배경색
- 숫자 정렬, 항목명 정렬, 들여쓰기
- 셀 여백과 행 높이
- N/% 표시 형식
- 표 폭 맞춤 방식

한글 템플릿 필드 규칙:

```text
REPORT_TITLE
REPORT_DATE
ANALYSIS_{table_key}
TABLE_{table_key}
CHART_{table_key}
NOTE_{table_key}
```

예:
- `ANALYSIS_T0003`
- `TABLE_T0003`
- `CHART_T0003`

한글 자동화 실행 절차:
1. 한글 실행 또는 기존 한글 객체 연결
2. 템플릿 파일 열기
3. 필드 목록 읽기
4. Excel `_ReportMeta`의 매핑과 필드 목록 비교
5. 분석문 삽입
6. 집계표 삽입
7. 차트 삽입
8. 저장
9. 삽입 실패 필드와 사유를 로그에 기록

### 4.6 PowerPoint 보고서 브랜치

PowerPoint 자동화는 한글 자동화와 같은 중간 산출물을 사용한다.

PowerPoint 브랜치는 한글 보고서를 그대로 복제하는 용도가 아니라, 핵심 결과를 발표자료 형태로 요약하는 별도 산출물로 설계한다. 기본 구조는 표지, 전체 요약, 표별 핵심 결과, 부록 순서로 구성한다.

입력:
- PowerPoint 템플릿 `.pptx`
- 슬라이드별 자리표시자 이름 또는 텍스트 토큰
- Excel `보고서_분석문`, `보고서_삽입표`, `보고서_차트데이터`

자리표시자 규칙:

```text
{{REPORT_TITLE}}
{{ANALYSIS_T0003}}
{{TABLE_T0003}}
{{CHART_T0003}}
```

초기 구현:
- 표별 1슬라이드 자동 생성
- 제목, 분석문, 차트, 축약표 배치
- 집계표는 PPT 표 객체로 생성하거나 Excel 범위 붙여넣기 방식으로 삽입한다.
- 집계표 이미지 삽입은 허용하지 않는다.
- 템플릿의 마스터 스타일을 최대한 유지

### 4.7 기본 템플릿 생성

보고서 자동화 기능은 사용자가 별도의 한글/PPT 템플릿을 준비하지 않아도 실행되어야 한다. 따라서 프로그램은 기본 템플릿 파일을 생성하고, 그 파일을 새 보고서의 출발점으로 사용한다.

기본 생성 파일:
- `templates/default_hwp_report.hwp` 또는 실행 시점 생성 HWP 파일
- `templates/default_hwpx_report.hwpx`
- `templates/default_ppt_report.pptx`

템플릿 생성 원칙:
- 기본 템플릿은 원본으로 보존하고, 실행 시에는 항상 새 산출 파일로 복사 또는 생성한다.
- 새 산출 파일명은 `보고서명_YYYYMMDD_HHMM` 형식으로 만든다.
- 템플릿에는 표지, 목차, 요약, 표별 본문 영역, 부록 영역을 둔다.
- 분석문, 표, 차트 위치는 필드명 또는 자리표시자 토큰으로 관리한다.
- 사용자가 기관 표준 템플릿을 지정하면 기본 템플릿 대신 사용자 템플릿을 사용한다.

HWP/HWPX 기본 템플릿 구성:
- 표지: 보고서명, 프로젝트명, 작성일
- 요약: 주요 결과 요약 필드
- 본문 반복 블록: 표 제목, 분석문, 차트, 집계표, 주석
- 부록: 원본 표 목록 및 검토 로그

PPTX 기본 템플릿 구성:
- 표지 슬라이드
- 전체 요약 슬라이드
- 표별 결과 슬라이드
- 부록/방법 슬라이드

기본 필드명:

```text
REPORT_TITLE
PROJECT_NAME
REPORT_DATE
SUMMARY_TEXT
SECTION_TITLE_{table_key}
ANALYSIS_{table_key}
TABLE_{table_key}
CHART_{table_key}
NOTE_{table_key}
```

생성 방식:
- HWP는 Windows 한글 설치 환경에서 COM 자동화로 새 문서를 만들고 필드/누름틀을 삽입한 뒤 `.hwp`로 저장한다.
- HWPX는 ZIP/XML 기반 문서 구조를 직접 생성하거나, HWP COM으로 만든 문서를 HWPX로 저장하는 방식을 우선 검증한다.
- PPTX는 Python `python-pptx` 또는 TypeScript 기반 PPTX 생성 라이브러리로 직접 생성한다.
- 집계표는 이미지가 아닌 편집 가능한 표 또는 붙여넣기 객체로 삽입한다.
- 차트는 HWP에서는 선택 붙여넣기 메타파일, PPT에서는 네이티브 차트 또는 이미지 삽입을 우선 검토한다.

MVP에서는 다음 순서로 지원한다.
1. PPTX 기본 템플릿 생성
2. HWP 기본 템플릿 생성
3. HWPX 저장 또는 변환 지원

HWPX 직접 생성은 문서 스펙과 호환성 검증 부담이 크므로, 한글 COM 자동화가 가능한 환경에서는 HWP COM 저장/변환 경로를 우선한다.

### 4.8 Markdown/Word/PDF 보고서 확장

엑셀 집계표 MVP 이후에는 Markdown을 원천 문서로 사용해 Word/PDF/HWP/PPTX로 확장 가능한 보고서 작성 흐름을 지원한다.

원칙:
- Markdown은 원문 편집과 버전관리를 위한 기준 산출물로 사용한다.
- Word/PDF 변환 시 Markdown 표가 깨지지 않도록 별도 표 객체 또는 변환 전용 표 모델을 사용한다.
- 보고서 유형별 기본 목차를 제공한다.
- Word/PDF 출력은 표 너비, 줄바꿈, 제목 계층, 페이지 나눔을 자동 조정한다.

기본 보고서 템플릿:
- 공공조사 보고서형: 요약, 조사 배경 및 목적, 조사 설계, 주요 결과, 세부 분석, 시사점, 정책 제언, 한계 및 후속 과제, 부록
- 제안서형: 제안 배경, 현황 및 문제 인식, 제안 방향, 세부 추진 방안, 방법론 및 산출 체계, 기대효과, 수행체계 및 일정, 산출물 구성
- 설문기획형: 개발 목적, 기존 문항 검토, 신규·개선 문항 요약, 주제별 문항 구성, 문항 로직, 실제 문항 예시, 산출 가능 지표, 기대효과
- 방법론 설명형: 검토 배경, 기존 방식의 한계, 대안 방법론의 이론적 배경, 적용 방식, 산출식 및 변수 정의, 기대효과, 적용 시 유의사항, 결론
- 회의록형: 회의 개요, 고객사 요청사항, 제안사 제안사항, 협상 및 조정사항, 결정사항, 후속 조치

### 4.9 품질검토 QA

보고서 자동화는 초안 생성보다 검토 가능성이 중요하므로 QA를 별도 단계로 둔다.

작성 전 QA:
- 산출물 유형 확인
- 입력자료 반영 여부 확인
- 기존 자료와 신규 자료 구분
- 유지 조건과 변경 금지 조건 확인
- 출처 필요 항목 식별

작성 중 QA:
- 목차와 산출 목적 일치 여부
- 문항, 지표, 산출식, 변수 정의 연결 여부
- 표/그래프와 본문 해석 수치 일치 여부
- 고객사 요구사항과 제안사 제안사항 혼동 여부

작성 후 QA:
- 수치 계산, 합계, 비율, 증감률 재검산
- 단위, 기준시점, 표본수, 모수, 응답 기준 일관성
- 문체 일관성
- 표 서식 깨짐 여부
- 출처 누락 여부
- 사용자 이전 피드백과 충돌 여부

수치 불일치나 출처 불명확 항목은 자동으로 확정문에 반영하지 않고 `보고서_QA`에 경고로 남긴다.

### 4.10 출처 관리 및 최신성 검토

자료조사 보고서, 정책보고서, 제안서에서는 출처 관리를 선택 기능으로 제공한다.

원칙:
- 원문 보고서, 논문, 공식 통계, 기관 발표자료를 기사보다 우선한다.
- 최신성이 중요한 주제는 발행일과 접속일을 기록한다.
- 출처가 불명확한 수치는 단정적으로 작성하지 않는다.
- APA 형식 참고문헌 생성을 장기 확장 기능으로 둔다.

출처 메타데이터는 `보고서_출처` 시트와 외부 워커의 `citations.json`에 동시에 저장할 수 있다.

- `실행 로그`

MVP에서는 UserForm을 최소화하고, 생성된 설정 시트에서 옵션을 수정하게 한다. 이후 표 선택, 템플릿 선택, 필드 매핑은 UserForm 마법사로 확장한다.

장기 화면 구성:
- 프로젝트 대시보드: 프로젝트 목록, 최근 수정일, 산출물 유형, QA 상태, 미해결 요구사항
- 자료 입력 화면: 파일 업로드, URL 입력, 자료 역할 지정, 문서 요약 미리보기, 출처 메타데이터 입력
- 보고서 생성 화면: 산출물 유형, 목차, 문체, 분량, 표/그래프/수식 포함 여부
- 검토 화면: 목차, 본문, 출처, 수치 QA, 피드백, 변경 전후 비교
- 출력 화면: Markdown, Word, PDF, PPTX, Excel, HWP/HWPX, 이미지 자산 출력

## 6. 예외 및 검증 규칙

표 인식 경고:
- 표 제목은 있으나 BASE 행이 없음
- 헤더가 3행 안에서 해석되지 않음
- N/% 쌍이 깨져 있음
- 같은 표 번호가 여러 번 등장함
- 숫자처럼 보여야 하는 값이 문자열임
- 병합 셀 때문에 상위 헤더가 누락됨

분석문 생성 경고:
- 분석 대상 값이 모두 0 또는 결측
- 전체 행이 없음
- 비교 기준 행/열이 없음
- 표본 수 기준 미달
- 순위 동률 발생

한글/PPT 삽입 경고:
- 템플릿 파일 없음
- 필드명 불일치
- 한글 COM 객체 생성 실패
- 한글 보안 모듈 등록 실패
- 차트 객체 생성 또는 붙여넣기 실패
- 저장 경로 접근 실패

보고서 작성 QA 경고:
- 출처 불명확
- 수치 불일치
- 표가 너무 넓어 본문 삽입 곤란
- 문항 중복 또는 신규/개선 분류 오류 가능성
- 사용자 지시 충돌
- 파일 손상 또는 자료 추출 실패

## 7. 기술 구조

현재 프로젝트는 Excel 추가 기능 기반이지만, 보고서 자동화 전체를 VBA만으로 구현하지 않는다. VBA는 Excel 안의 실행 버튼, 설정 시트, 검토 시트, 기존 집계표 처리 기능을 담당하고, 파일 생성과 한글/PPT 자동화는 외부 워커가 담당하는 하이브리드 구조를 기본으로 한다.

역할 분리:
- VBA: Excel 리본 UI, 설정/검토 시트, 기본 표 탐지, 외부 워커 실행
- Python 또는 TypeScript 워커: 분석 규칙 처리, 템플릿 생성, HWP/HWPX/PPTX 파일 조립, 문서/파일 입출력
- Excel 산출 시트: VBA와 외부 워커 사이의 안정적인 교환 포맷

이 구조를 쓰는 이유:
- HWP/HWPX/PPTX는 파일 생성과 템플릿 조립이 핵심이므로 VBA만으로 유지보수하기 어렵다.
- Python/TypeScript는 JSON, ZIP/XML, PPTX, 문서 조립 처리 라이브러리가 풍부하다.
- VBA는 사용자가 Excel에서 버튼을 누르고 결과를 검토하는 경험에는 적합하지만, 복잡한 문서 생성 엔진으로 쓰기에는 테스트와 배포가 어렵다.
- 외부 워커를 두면 나중에 GUI 앱, CLI, 배치 처리, 서버형 변환기로 확장하기 쉽다.

권장 기술 선택:
- 1순위: Python 워커
  - Excel/CSV/JSON/PPTX 처리와 Windows COM 제어가 쉽다.
  - HWP 자동화는 `win32com` 계열로 PoC한다.
  - PPTX는 `python-pptx` 계열로 기본 템플릿과 보고서 생성이 가능하다.
- 2순위: TypeScript/Node 워커
  - JSON 규칙 엔진, CLI 패키징, 향후 웹 UI 확장에 좋다.
  - PPTX 생성은 가능하지만 HWP COM 제어는 Python보다 번거로울 수 있다.
- 결론: 초기 구현은 Python 워커를 기본으로 하고, TypeScript는 향후 웹/데스크톱 UI 또는 규칙 편집기로 확장할 때 검토한다.

패키징 정책:
- PoC와 테스트 버전에서는 Python 워커를 `.exe`로 패키징하지 않는다.
- 테스트 단계에서는 저장소의 Python 소스를 직접 실행해 개발 속도와 디버깅 가능성을 우선한다.
- `.exe` 패키징은 Excel 산출 시트, PPTX 생성, HWP COM 연동의 뼈대가 안정화된 뒤 배포 단계에서 검토한다.
- 패키징 전까지는 프로젝트 폴더 안의 Python 가상환경을 기준 실행 환경으로 사용한다.
- Python 실행 경로, 가상환경 활성화 여부, 의존 패키지 설치 여부, 워커 실행 로그를 설정/진단 시트에 명확히 표시한다.

실행 구조:

```text
Excel Add-in VBA
  -> 보고서_설정 / 보고서_분석문 / 보고서_삽입표 / _ReportMeta 생성
  -> VBA 기본 단계 완료
  -> 사용자가 HWP/PPT 후속 생성을 선택
  -> python report_worker.py --job job.json 실행
  -> worker가 기본 템플릿 생성 또는 사용자 템플릿 복사
  -> worker가 HWP/HWPX/PPTX 보고서 생성
  -> worker_result.json과 실행 로그를 Excel로 반환
```

장기 확장 구조:

```text
Project Workspace
  -> inputs / working / outputs / logs
  -> source parser
  -> requirement parser
  -> report outline engine
  -> analysis and table engine
  -> QA engine
  -> export engine
```

권장 모듈:
- `ReportAutomation_Core.bas`: 실행 흐름, 공통 타입, 로그
- `ReportAutomation_TableParser.bas`: 표 블록 탐지 및 정규화
- `ReportAutomation_Narrative.bas`: 분석문 생성
- `ReportAutomation_Chart.bas`: 차트 데이터 및 차트 생성
- `ReportAutomation_OutputSheets.bas`: 결과 시트 생성
- `ReportAutomation_QA.bas`: 수치/문체/표 서식 검토 결과 시트 생성
- `ReportAutomation_Source.bas`: 출처와 자료 역할 메타데이터 관리
- `ReportAutomation_Hwp.bas`: 아래아한글 COM 연동
- `ReportAutomation_Ppt.bas`: PowerPoint 연동
- `ReportAutomation_Forms.bas`: UserForm 연결

외부 워커 권장 구조:
- `report_worker/main.py`: CLI 진입점
- `report_worker/job_schema.py`: VBA와 주고받는 JSON 스키마
- `report_worker/project_store.py`: 프로젝트, 요구사항, 수정 이력 저장
- `report_worker/source_parser.py`: Markdown, Word, PDF, PPTX, Excel, CSV, 텍스트 추출
- `report_worker/requirement_parser.py`: 산출물 유형, 제약, 문체, 출처 필요 여부 추출
- `report_worker/report_outline.py`: 보고서 유형별 목차 생성
- `report_worker/llm_client.py`: GPT/Claude API 호출과 응답 검증
- `report_worker/qa_engine.py`: 수치, 출처, 문체, 표 서식 QA
- `report_worker/citation_manager.py`: 출처 메타데이터와 참고문헌 관리
- `report_worker/formula_renderer.py`: 산출식과 변수 정의 렌더링
- `report_worker/survey_module.py`: 설문문항과 로직 구조도 생성
- `report_worker/methodology_module.py`: 표본설계, 시장규모, PSM 등 방법론 설명 생성
- `report_worker/template_hwp.py`: HWP/HWPX 기본 템플릿 생성 및 삽입
- `report_worker/template_pptx.py`: PPTX 기본 템플릿 생성 및 삽입
- `report_worker/export_markdown.py`: Markdown 보고서 생성
- `report_worker/export_docx_pdf.py`: Word/PDF 변환
- `report_worker/assets.py`: 차트 객체 데이터, 임시 파일 관리
- `report_worker/logging.py`: 실행 로그와 오류 반환
- `templates/`: 기본 템플릿 원본 또는 생성용 리소스

중장기 확장:
- 복잡한 문장 생성이나 규칙 관리가 커지면 외부 JSON 규칙 파일을 도입한다.
- 한글/PPT 자동화가 VBA에서 불안정하면 Python 또는 .NET 보조 실행 파일로 COM 제어를 분리한다.
- 외부 LLM 기반 문장 고도화는 반드시 검토 시트와 원문 수치 추적을 전제로 한다.
- 민감한 조사자료를 고려해 로컬 우선 실행 모드를 제공한다.
- 외부 자료조사와 최신성 검토가 필요한 경우에만 웹 검색 모듈을 활성화한다.

## 9. 구현 단계

### M0. PoC

목표:
- 샘플 통합문서에서 127개 표 블록 탐지
- 표 목록 시트 생성
- 첫 5개 표의 전체 행 기준 분석문 생성

완료 기준:
- `보고서_표목록`에 모든 표가 나타남
- 표 제목, 원본 범위, 유형이 맞음
- 최소 3개 유형의 표에서 분석문이 생성됨

### M1. Excel 산출물 MVP

목표:
- 설정 시트 생성
- 표 선택 기능
- 분석문 시트 생성
- 차트 데이터 시트 생성
- 삽입표 시트 생성

완료 기준:
- 사용자가 표를 선택하고 분석문/표/차트를 재생성할 수 있음
- 원본 수치와 표시 수치가 분리됨
- 실행 로그가 남음

### M1.5. 외부 워커 및 기본 템플릿 PoC

목표:
- VBA에서 Python 워커를 호출한다.
- `job.json`과 `worker_result.json` 교환 구조를 만든다.
- 기본 PPTX 템플릿을 새 파일로 생성한다.
- 한글 설치 환경에서 기본 HWP 파일 생성 가능 여부를 확인한다.
- 워커는 소스 실행 방식으로 검증하며 `.exe` 패키징은 하지 않는다.
- 프로젝트 폴더 안의 Python 가상환경에서 워커를 실행한다.

완료 기준:
- Excel 버튼 실행으로 PPTX 기본 보고서 파일이 생성됨
- 워커 실행 성공/실패가 Excel 로그 시트에 기록됨
- HWP COM 객체 생성 가능 여부와 저장 가능 여부가 로그에 기록됨
- Python 실행 경로와 의존성 오류가 사용자에게 이해 가능한 메시지로 표시됨

### M2. 문장 규칙 고도화

목표:
- 상위/하위, 전체 대비, 집단 간 비교 지원
- 템플릿 문장 변수 지원
- 사용자 수정문 우선 반영

완료 기준:
- 같은 표에 대해 2개 이상의 문장 논리를 선택 가능
- 수치 출처가 추적됨

### M2.5. LLM 문장 고도화 옵션

목표:
- `보고서_설정`에서 OpenAI GPT 또는 Anthropic Claude API 키를 입력받는다.
- 규칙 기반 분석문과 주요 수치 JSON을 바탕으로 문장 고도화 결과를 생성한다.
- LLM 결과를 `분석문_LLM` 열에 저장하고 사용자가 선택적으로 최종문에 반영한다.

완료 기준:
- API 키가 없는 경우에도 규칙 기반 분석문 생성은 정상 동작함
- LLM 호출 실패가 전체 보고서 생성 실패로 이어지지 않음
- LLM이 생성한 문장에 사용된 수치가 원본 주요 수치와 불일치하면 경고가 표시됨
- API 키는 기본적으로 통합문서에 평문 저장되지 않음

### M3. 한글 자동화 MVP

목표:
- 한글 템플릿 열기
- 필드 목록 확인
- 분석문 필드 삽입
- 보고서 파일 저장

완료 기준:
- `ANALYSIS_{table_key}` 필드에 최종 사용문 삽입
- 실패 필드가 로그에 기록됨

### M4. 한글 표/차트 삽입

목표:
- 보고서용 집계표 삽입
- 차트 객체 또는 Excel 차트 붙여넣기 삽입
- 기본 서식 적용

완료 기준:
- 한글 보고서에 분석문, 표, 차트가 모두 들어감
- 표 폭과 차트 크기가 템플릿 영역을 벗어나지 않음

### M5. PowerPoint 브랜치

목표:
- PPT 템플릿 기반 보고서 초안 생성
- 표별 슬라이드 자동 생성
- 분석문/차트/표 배치

완료 기준:
- 선택한 표 수만큼 슬라이드 생성
- 템플릿 스타일 유지
- 차트와 표가 겹치지 않음

### M6. Markdown/Word/PDF 보고서 확장

목표:
- Markdown 기반 보고서 초안을 생성한다.
- 공공조사, 제안서, 설문기획, 방법론, 회의록 템플릿을 제공한다.
- Markdown 표를 Word/PDF에서 깨지지 않는 표 객체로 변환한다.

완료 기준:
- 같은 입력자료로 Markdown 보고서와 Word/PDF 산출물을 생성할 수 있음
- 표 제목, 단위, 기준, 주석이 보존됨
- 문체 프로필이 보고서 전체에 적용됨

### M7. 출처/QA/수정이력 확장

목표:
- 출처 메타데이터와 APA 참고문헌 생성을 지원한다.
- 수치, 출처, 문체, 표 서식 QA를 실행한다.
- 사용자 피드백 기반 수정 이력을 관리한다.

완료 기준:
- QA 결과가 `보고서_QA`와 `qa_results.json`에 기록됨
- 출처 목록이 `보고서_출처`와 `citations.json`에 기록됨
- 수정 전후 내용이 `보고서_수정이력`과 `revisions.json`에 기록됨

### M8. 설문·방법론·산출식 모듈

목표:
- 설문문항 신규/개선/유지 분류와 문항 로직 구조도를 생성한다.
- 표본설계, 시장규모, PSM, 복수응답 분석 등 방법론 설명을 생성한다.
- 한글 변수명 기반 산출식과 변수 정의를 생성한다.

완료 기준:
- 설문문항 개발, 시장규모 산출식, 표본설계 설명 중 3개 이상 반복 업무를 자동화함
- 산출식, 변수 정의, 적용 문항, 해석 문장이 함께 생성됨
- 사용자가 유지하라고 한 설문 구조를 임의로 변경하지 않음

## 11. 검토 질문

다음 항목은 사용자 결정으로 확정한다.

확정 사항:
- VBA 단계의 최종 산출물은 Excel 산출 시트로 한다.
- HWP/PPT는 사용자가 후속으로 선택 실행한다.
- 집계표 이미지 삽입은 허용하지 않는다.
- 집계표는 가능하면 HWP/PPT 네이티브 표로 생성하고, 차선책으로 붙여넣기를 허용한다.
- 붙여넣기 방식에는 표 서식 설정창을 반드시 제공한다.
- HWPX 직접 생성은 후순위로 둔다.
- 초기 테스트 단계에서는 Python 워커 `.exe` 패키징을 하지 않는다.
- 가중 사례수와 실제 사례수는 모두 보존한다. 기본 보고서 표시는 가중 사례수와 비율 중심으로 하되, 실제 사례수는 검토/주석/메타데이터에서 확인 가능하게 한다.
- PowerPoint 브랜치는 한글 보고서 전체 복제가 아니라 발표용 요약 보고서로 설계한다.
- 표 서식 설정창의 기본값은 공공/연구보고서형 기본 양식을 기준으로 한다.
- GPT/Claude API 키 입력란을 제공하되, LLM은 규칙 기반 분석문을 보완하는 선택 기능으로 둔다.
- 비율 표기는 기본적으로 소수점 1자리까지 표시한다.
- 차트는 이미지 삽입을 허용한다.
- HWP 차트 삽입은 선택 붙여넣기 기능으로 메타파일 형식을 우선한다.
- Python 테스트 실행 환경은 프로젝트 폴더 안의 가상환경을 기준으로 한다.

추가 확인이 필요한 항목:

1. 분석문 문체는 기존 보고서 문장을 학습한 예시가 있는가?
2. 차트 스타일은 기관 표준이 있는가?
3. API 키 저장은 실행 시 입력만 허용할 것인가, Windows 자격 증명 관리자 등 별도 보관 방식을 제공할 것인가?

## 12. 수용 기준

엑셀 집계표 기반 초기 버전은 다음 기준을 만족하면 성공으로 본다.

- 샘플 집계표에서 표 127개를 자동 탐지한다.
- 표별 원본 범위와 제목을 추적한다.
- 사용자가 선택한 표에 대해 분석문과 보고서용 삽입표를 생성한다.
- 생성된 분석문은 사용자가 Excel에서 수정할 수 있다.
- HWP/PPT 후속 생성을 위한 메타데이터와 워커 실행 입력 파일을 생성한다.
- 실패/경고 내역이 별도 로그 또는 시트에 남는다.
- 원본 집계표 값은 변경하지 않는다.

상위 보고서 작성 자동화 1차 완성 기준:
- 사용자가 주제와 자료를 입력하면 Markdown 보고서 초안을 자동 생성한다.
- 보고서 초안은 사용자 선호 문체와 기본 목차 구조를 반영한다.
- 표, 수치, 산식, 변수 정의, 출처가 누락되지 않도록 QA 결과를 제공한다.
- Word와 PDF로 변환해도 표 서식이 크게 깨지지 않는다.
- 사용자의 수정 지시를 반영하여 동일 보고서를 재생성할 수 있다.
- 설문문항 개발, 시장규모 산출식, 표본설계 설명 등 핵심 반복 업무를 최소 3개 이상 자동화한다.
